# Spec Review

**Trigger:** "review this spec", "verify the spec", "run spec review", "gap analysis".

The review runs as Workflow stages of one script, `scripts/spec-review.workflow.js`, which holds agent work only (it has no shell; no LLM agent runs a command). Every command is a Bash gate, `scripts/stage.py <gate>` (`$S` below), that the main loop runs between stages; each gate prints the exact args of the next stage. Codex lanes run through `scripts/run-codex-lanes.sh`. The main loop reads `report.md`, applies the spec-prose fixes and commits. Lane data (agent types, models, gates, tiers, budgets) lives only in `lanes.json` (plus optional per-repo `<root>/.claude/spec-review.lanes.json`, merged by `run_dir.py plan`); briefs only in `prompts/`; the report shape only in `report-template.md`.

**Mandatory, depth tiered by risk.** Every spec is reviewed before build; only the depth varies. This skill IS the user's opt-in to the Workflow tool: call it as written below.

**Skill memory.** The script hands lanes and synthesis the LEARNINGS paths (committed `LEARNINGS.md`, private overlay `~/.claude/skills-overlay/spec-review/LEARNINGS.md`); the main loop does not read them. At the end, route each learning: operator-private craft to the overlay, project facts to the project's `.claude/memory/`, universal craft to `/improve-harness`. Never append to the committed `LEARNINGS.md`. Routing: [`docs/skill-memory.md`](../../../docs/skill-memory.md).

> **Findings, not procedures.** The review fixes real design defects in the spec's *prose* and must NEVER put its scaffolding (EC/Sec/Obs/DRIFT tables, matrices, lane lists) into the spec. Those live in the report. For `critical`, `standard` and `light` the report ships as `<spec-without-.md>.review.md`, committed with the spec; `hotfix` keeps it in the run dir. Downstream consumers must degrade gracefully when it is absent.

## Flow

**Step 1. Frame (main loop, one turn).** Confirm the spec and read it. Decide, from the spec and the conversation:
- **Why block**, 5-10 lines: Goal, Trigger, Target outcome, Scope boundaries (ruled-out items).
- **Tier** (logged, never silent; blast radius is the risk axis, not line count): `critical` (only a cynap repo, never tooling/harness-only, and only with a floor domain: access/authn/authz/credentials/tenancy/billing/money/personal data/erasure, high-level architecture, deep infrastructure, shared-store migrations, a cutover that is shared-store, prod-traffic or credential-bearing; tier follows the CHANGED surface, so a docs-only spec that specifies a money, security, tenancy, credential or shared-infrastructure change keeps the floor, and so does a shared reader/writer used by every Lambda or code that kills process trees or sandboxes; `plan` refuses it otherwise (run `standard`); profile `full`, ALL gate-fired lanes, frontier judge, falsifier on every CRITICAL and each MAJOR only one lane raised), `standard` (every other behavior-bearing spec: completeness, codebase-verifier, edge-case, dependency-currency, one frontier judge, plus gate-fired lanes; falsifier on CRITICAL only), `light` (low-risk local change with NO gate fired: docs/config/copy/UI-only/internal tooling; codebase-verifier, edge-case, one judge, no falsifier), `hotfix` (prod down, minutes matter). Tier detail and overrides: [`reference.md`](reference.md#tiers-lane-plan-per-repo-lanes-and-budgets).
- **Gates**, each `{run: boolean, reason: string}` (the reason is printed in the report either way; a fired gate's reason must quote its evidence, a path, file:line or identifier, or `run_dir.py plan` rejects it): `liveSurface` (changes a deployed artifact AND names it: file:line, Lambda, table, route, flag or prod config key; not spec-only, local tooling or read-only evidence), `security` (adds a credential, table or authz surface), `cutover` (removes or replaces an existing capability, store or contract owner AND states a switch-over step: backfill, dual-run, flag flip or deleted old path; additive fields, bug fixes and library bumps do not fire it), `runtimeWiring` (adds a runtime-read env var/secret/flag/URL, a deployed function, or moves such a read into shared code), `operatorSurface` (adds or changes a feature, entity, setting or action an operator must reach, query or drive), `legalSurface` (touches personal data, a data recipient or vendor, consent/acceptance/disclosure UX, retention or erasure, billing terms or AI disclosure; the legal lane also runs in every `critical`), `decisionSurface` (hard-codes a decision a fast model could make: routing, classification, matching, thresholds, UI or assistant behaviour, tool/integration choice). The `dependency-currency` lane runs in every tier but `light`, with no gate: installed vs latest versions, open CVE/GHSA advisories joined to CISA KEV with reachability, changelogs since the installed version, current vendor docs via Context7, and workarounds a newer version removes. Fired gates are non-droppable.
- **`lanePlan`** `{tier, add: [labels], drop: [labels], reasons: {label: why}}`: your lane choice on top of the tier's default set, every add/drop with a reason. `run_dir.py plan` rejects an unknown label, any drop at `critical`, any drop of the frontier or codebase-verifier lane or of a lane whose gate fired, and `light` with any gate fired; reasons print in the report either way. Other repos skip the cynap-only legal and operator-plane lanes. Write `{repo, harnessOnly, floorDomain, gates, lanePlan}` (`repo` = the spec's repo name; `floorDomain` = the floor domain for `critical`, else empty) to `<runDir>/inputs/frame.json`, then run `python3 <skill-dir>/scripts/run_dir.py plan --run <runDir> --root <root> --input <runDir>/inputs/frame.json` and fix what it rejects. It writes the one resolved manifest and plan every later stage reads.
- **`sid`**: `$CLAUDE_SESSION_ID`; on a RESUMED session with an empty transcript, the prior session's id from `Session-Id` trailers on commits touching the spec. From a Codex session pass `runtime: "codex"` and the rollout id.
- **`runDir`**: a fresh absolute directory in the scratchpad, e.g. `<scratchpad>/spec-review-<timestamp>`.

**Step 1b. Why gate (one Opus lane).** `python3 $S/stage.py why-gate --run <runDir> --spec <spec> --root <root> --ticket <CYN-n> [--docs-only <reason>]` prints the `{stage:"why"}` args (`hotfix` or `--docs-only` skips); after the lane, `why-gate --check`: PROCEED joins the why record to the context; SIMPLIFY or WRONG-ROUTE hard-stops (grill the founder, recommended answer first, rerun) and `prepare` refuses. [`reference.md`](reference.md#why-gate).

**Step 2. Prepare (main loop Bash, then Workflow only on a Codex miner failure).** The Workflow tool refuses the installed skill dir, so first `cp <skill-dir>/scripts/spec-review.workflow.js <runDir>/../spec-review.workflow.js`; reuse that copy for every stage, never inline. Write the why block to `<runDir>/inputs/context.md`, then `python3 $S/stage.py prepare --run <runDir> --spec <spec> --root <root> --sid <sid> [--runtime codex] [--prior <earlier runDir>]`. Pass `--prior` when the spec was already reviewed (a re-review after fixes): it reuses that run's dossier and picks the depth itself, `fix-verify` (edit of 150 changed lines or fewer, no newly fired gate: floor lanes plus the lane that raised each applied finding) or `delta` (anything larger: also the fired-gate lanes and lanes citing a changed section) ([`reference.md`](reference.md#run-costs-what-this-skill-spends)). Without it, run the returned `extractCommand` in the background (`run-codex-lanes.sh <runDir> extract`: the dossier and decisions miners on Codex, graded by artifact); if its JSON lists a `fallback` miner (DEAD, BLOCKED-ON-QUOTA or invalid), run Workflow `{stage:"prepare", fallback:[...]}` for just that one. Then `python3 $S/stage.py finish-prepare --run <runDir> --spec <spec>`: it fills every lane prompt and returns `reviewLanes`, `codexCommand` and the gate notes.

**Step 3. Review wave (one turn, parallel calls).** In ONE message: (a) `Bash` with `run_in_background: true` running `codexCommand` (Codex dispatches, then luna envelope extraction; never `&`/nohup); (b) `Workflow` `{stage:"review", lanes:<reviewLanes>}`; (c) for `critical` on Claude Code, the investigation skill on the spec's 3-6 core themes (premise: "Ground the industry standard + best-in-class elevation for these spec themes, framed against THIS codebase: `<themes>`. Spec: `<path>`. Return verified evidence, each claim code-anchored or with a live source URL"), which writes `docs/investigations/YYYY-MM-DD-<slug>.md`; when `decisionSurface` runs, one theme is fast-model decision placement. Do not poll. Then `stage.py post-review --run --spec`: `ok:false` with `failed` and `relaunch` means a lane wrote no envelope, so run Workflow with `relaunch` and rerun it; when it returns `needReview2`, run Workflow with its `review2Args` and rerun it with `--final`. `quotaStopped:true` (any gate) means a session/weekly limit: STOP, launch nothing more, list `notRun` as "not run: quota", resume only after the reset via `stage.py quota-clear`. A `hardStop` in its output stops the run.

**Step 4. Synthesize (after ALL of: the Codex wrapper, the review stage, the investigation).** Repeat until the gate says to move on: `stage.py synth-prep --run --spec` (`pending` means run Workflow `criticsArgs`, an Opus `critic` for a dead adversarial or Astra lane or a Claude envelope extractor, then rerun it); if `mergeNeeded`, Workflow with `mergeArgs`; `stage.py falsify-prep` (it validates the merge, applies the ceiling, and returns `falsifyArgs`; a merge it rejects returns `mergeArgs` with `repairErrors`, at most twice); Workflow `falsifyArgs`; `stage.py falsify-check [--investigation <brief>] [--review-path <abs .review.md>]` (a `redo` reruns its batches once); Workflow `reportArgs`; `stage.py report-check`, which fails the run unless: the falsifier line matches the real counts, every CRITICAL/MAJOR envelope id is in the report with a verdict, every lane is listed as run, carried or `SKIPPED (gate: <reason>)`, the Astra lane (or its critic) produced a result, and `validate_review_report.py` passes; on errors rerun Workflow `reportArgs` plus `repairErrors`. Gates print `SPEND WARNING` at the tier's `tokenCeiling`, `SPEND STOP` at 1.5x, and `report-check` leaves `<runDir>/lane-spend.json`.

**Step 5. Read, decide, fix (main loop).** Read `report.md` (it is the only findings text the main loop ever reads). If `hardStop` is true, stop; `hardStopReasons` says why: `adr` (an Accepted ADR/invariant changed) or `legal` (an in-force legal commitment breached), each without a founder-approval marker, or a gate lane with no usable verdict (relaunch it). If it lists System 1 research hand-offs (`S1-Hn`), send them to the investigation skill in one call before applying any S1 elevation. For genuine Claude-vs-Codex judgment splits see [`reference.md`](reference.md#step-5b--cross-examination-debate-protocol-moved-detail).

**Step 5c. Fix policy.** Apply CRITICAL and MAJOR defects that SURVIVED the falsifier wave by fixing the actual design problem in the spec's own prose (the mechanism, the boundary, the auth rule), as a one-line behavioral statement. Then record what you did: `python3 $S/stage.py mark-applied --run <runDir> --ids F-1,F-3` for the units you applied (`--status false` for ones you decided against); the `applied` field defaults to null. Never paste a finding's table row, an EC/Sec/Obs/DRIFT id, a matrix or lane list into the spec. Present every EC/Sec/Obs/Drift/Industry finding to the user; Industry Insights and CAUTION items are never auto-applied. Out-of-scope findings go to a separate issue. An unrefuted CRITICAL is never downgraded by instinct.

**Step 9. Commit.** `git add <spec> <spec>.review.md`, then `git commit -F <msgfile> --trailer "Session-Id: $CLAUDE_SESSION_ID"` with a message like `docs(<scope>): spec review fixes, <N> issues from the multi-lane pipeline`. Optional follow-ups (alignment investigation, visualization; off by default): [`reference.md`](reference.md).

## Args contract

`$S` = `<skill-dir>/scripts`. Every Workflow call passes `stage`, `runDir`, `skillDir` (this skill's absolute directory) and `spec`, plus the args its gate printed:

| stage | extra args (printed by) |
|---|---|
| prepare | `fallback` (the extract run) |
| review | `lanes` (`finish-prepare`) |
| review2 | `briefs`, `repair` (`post-review`) |
| critics | `critics`, `extractors` (`synth-prep`) |
| merge | `ok`, `indexPath`, `totalIds`, `repairErrors?` (`synth-prep`, `falsify-prep`) |
| falsify | `batches` (`falsify-prep`, `falsify-check`) |
| report | `briefPath` (`falsify-check`), `repairErrors?` |

Workflow stages return only labels and gate notes, never findings; run state is `<runDir>/state.json`.

## Process gates

- **Review before build, no exceptions.** No spec ships to build without a review at or above its tier; skipping is not an option. Any fired gate forces `standard` or above with that lane, never `light`.
- **No build dispatch past an unresolved sequencing drift finding** (`sequence-after <PR/spec>` is a refusal until resolved or overridden by the user).
- **Grill precedes review** when the premise was never interrogated; a failed why gate forces it.

## Light and trivial specs

No skip path: a trivial spec (<50 lines, no gate fired) or pure docs change takes tier `light`. `--skip-alignment` skips the optional alignment investigation.
