# Spec Visualization Learnings

## What Worked

- For a surface spanning several finalized specs, the latest closure spec can serve as the dashboard anchor while its `Extends`, `Integrates`, and `Preserves` links define the canonical companion set.
- Keeping present production truth in badges, a dedicated component card, and gate decisions prevents historical conformance receipts from being mistaken for the current score.

## Patterns

- A ten-node spine at the required 230px stride remains readable while still covering authoring, compilation, exact proof, release control, runtime, and cleanup. Put the clinical feedback loop at `y: 340` and engine-only rollback at `y: 520` so the two backward edges never share a lane.
- Collapse append-only review state into the workbench node and capability-separated artifacts into the compiler node; preserve their detail in Components instead of widening the flow.
- A 12-phase transactional spine should not be fit into a 1400px viewport. Give it a fixed wide canvas inside a local horizontal scroller; this preserves strict authority, preemption, and recovery lanes while keeping node labels readable and preventing whole-page overflow.
- When deployment identity itself schedules proof, show the scheduler and atomic execution-attestation writer as distinct spine stages before the release gate. This prevents a successful run or clean-source attestation from visually implying activation authority.
