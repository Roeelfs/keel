DEEP-WORKFLOW.md:138 names "the SOURCES.md tiers" with no path and no inlined content, and a Workflow agent() lane starts cold — so rows added to the catalog today are a no-op on lane behavior. Two of the existing 15 rows (gh search code :16, Sourcegraph :18) are already dead letters under the lane's WebSearch+WebFetch-only grant, and GitHub CODE search is 401 unauthenticated. I hand-hit ~90 endpoints on 2026-08-18 and confirmed 29 WebFetch-callable primary channels across five families the catalog has ZERO rows for: community forums (Discourse /search.json, GitHub Discussions), package/security registries (deps.dev — one URL shape across 7 ecosystems), agent/MCP/skill registries, status/changelog/EOL feeds, and structured-knowledge/benchmark APIs. ## Problem frame

The investigation skill's grounding surface is bounded by three things, in this order. (1) DELIVERY — the research lane prompt (DEEP-WORKFLOW.md:138) references SOURCES.md by name only, so catalog growth is invisible to the lane; adding rows alone changes nothing. (2) ADMISSION — SOURCES.md:40-42 admits a source only if queryable via "a stable site: host or a CLI/URL search", which makes every public JSON/REST GET endpoint (npm, PyPI, deps.dev, endoflife.date, Statuspage, the MCP registry) illegal under the skill's own rule. (3) TRANSFORMATION — even a delivered, legal catalog hits a 5xN concept ceiling (`.slice(0, N)` at :133 after the frame asks for 4-8 questions; `.slice(0, 5)` at :143), a boolean `verified` field (:125), a different-domain corroboration requirement (:146) that penalizes exactly the primary sources the skill tells lanes to prefer, and a 40-character-prefix claim/verdict join with `false` fallthrough (:157-160) that silently converts an unmatched verdict into a refutation. The output schema (:168-184) is additionalProperties:false with no field for contrarian evidence, rejected alternatives, or source-channel coverage, and only `industry_standard` carries per-item {point, source} — contradicting SKILL.md:33's one-URL-per-claim rule. The success metric is distinct domains/channels cited in the brief; the only committed brief cites 5 URLs across 3 domains, all vendor-owned (n=1, an existence proof, not a distribution). Cost frame: a default run is 14 agent calls, 38 at the N=12 clamp, and investigation is positioned as the cheap always-on gate — so prompt-string edits are the affordable direction and new phases are not.

## Industry standard

- Production multi-agent research does NOT adjudicate a claim by cross-domain corroboration. Anthropic runs a single LLM-judge call outputting 0.0-1.0 plus a pass/fail grade over five separate axes: factual accuracy, citation accuracy, completeness, source quality ("did it use primary sources over lower-quality secondary sources?"), and tool efficiency. Primary sources are REWARDED on the source-quality axis, not penalized for being uncorroborated.
  - https://www.anthropic.com/engineering/multi-agent-research-system
- The cheap adjudication shape is the correct one: "a single LLM call with a single prompt outputting scores from 0.0-1.0 and a pass-fail grade was the most consistent and aligned with human judgements" — a per-claim rubric call, not a per-claim research round.
  - https://www.anthropic.com/engineering/multi-agent-research-system
- Published verdict taxonomies are three- or four-valued and separate REFUTED from UNVERIFIED by construction. FEVER uses Supported/Refuted/NotEnoughInfo over 185,445 claims (Fleiss kappa 0.6841); baseline label accuracy is 31.87% when correct evidence is required vs 50.91% when evidence is ignored — verifying the evidence, not the verdict, is where the loss lives.
  - https://arxiv.org/abs/1803.05355
- AVeriTeC (4,568 real-world claims from 50 fact-checking orgs) adds a fourth, non-directional label — Supported / Refuted / Not Enough Evidence / Conflicting Evidence-Cherry-picking — for claims with both supporting and refuting sources. Verdict inter-annotator kappa 0.619.
  - https://fever.ai/dataset/averitec.html
- Attribution is joined to claims POST-HOC by a dedicated agent, not carried as a text key through the pipeline: the lead agent "passes all findings to a CitationAgent, which processes the documents and research report to identify specific locations for citations."
  - https://www.anthropic.com/engineering/multi-agent-research-system
- Width is the lever and it is priced directly in tokens: multi-agent systems "use about 15x more tokens than chats" versus ~4x for a single agent, and the system "outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval." Any proposal that adds a phase is a token proposal.
  - https://www.anthropic.com/engineering/multi-agent-research-system
- Source-quality drift is a named production defect fixed by PROMPT text, not by architecture: agents "consistently chose SEO-optimized content farms over authoritative but less highly-ranked sources like academic PDFs or personal blogs" until source-quality heuristics were added to the prompts.
  - https://www.anthropic.com/engineering/multi-agent-research-system
- Loop bounds in open-source deep-research implementations are named config fields with small integer defaults, never open-ended — local-deep-researcher's entire termination control is `max_web_research_loops: int = 3` in src/ollama_deep_researcher/configuration.py.
  - https://raw.githubusercontent.com/langchain-ai/local-deep-researcher/main/src/ollama_deep_researcher/configuration.py
- Package health across ecosystems has converged on ONE unauthenticated GET shape: api.deps.dev/v3/systems/{npm|pypi|cargo|maven|go|nuget|rubygems}/packages/{name} — verified 200 on all seven (npm/express 56 KB, pypi/requests 27 KB, cargo/serde 53 KB, maven guava, go gorilla/mux, nuget Newtonsoft.Json, rubygems/rails).
  - https://api.deps.dev/v3/systems/npm/packages/express
- Operational status has a stable public JSON convention: Atlassian Statuspage at https://<status-host>/api/v2/summary.json with top-level keys page, components, incidents, scheduled_maintenances, status. Probed 2026-08-18: status.claude.com returned 2,154 B JSON, page.updated_at 2026-08-18T07:49:12.565Z, status.indicator "none".
  - https://status.claude.com/api/v2/summary.json
- Vulnerability query APIs are POST-shaped by default and therefore un-callable from a WebFetch-only lane — GET https://api.osv.dev/v1/query returns HTTP 405 with an explicit "http method is not allowed" body (re-confirmed 2026-08-18). A catalog written for an agent must name the GET-able substitute, not the canonical API.
  - https://api.osv.dev/v1/query?package.name=lodash
- Structured-knowledge bodies publish a machine-readable index on a DIFFERENT host from the human site: W3C's is api.w3.org (HATEOAS, 1,710 specs over 570 pages), not www.w3.org/TR — whose tr.json returns HTTP 300, not JSON. TC39's is raw markdown at raw.githubusercontent.com/tc39/proposals/main/README.md.
  - https://api.w3.org/specifications?format=json&items=3

## Elevation (best-in-class)

- Replace the boolean `verified` with a five-axis single-call rubric plus a 5-value verdict enum. Anthropic's production system grades factual accuracy, citation accuracy, completeness, source quality and tool efficiency as distinct 0.0-1.0 dimensions in ONE call — and its source-quality axis rewards primary sources. That is strictly better than DEEP-WORKFLOW.md:146's different-domain rule, which inverts the same axis and makes a vendor-docs-only fact unverifiable by construction.
- Add AVeriTeC's fourth, non-directional label. A verdict set of {corroborated, primary_attested, contested, unverified, refuted} maps onto published practice: FEVER's NotEnoughInfo and AVeriTeC's Conflicting Evidence/Cherry-picking both exist precisely so a claim that cannot be resolved directionally is not forced into a direction. `primary_attested` is the terminal state a widened primary catalog needs.
- Recency as a query PARAMETER rather than a hope. Discourse accepts search operators inside the q= value — order:latest and after:YYYY-MM-DD — which turns a discussion corpus into a version-currency source; without them the endpoint returns relevance order and buries this month's threads under 2022's.
- Prefer endpoints that carry their own freshness field, so a claim reads "current as of <timestamp from the payload>" rather than "as of my fetch": endoflife.date v1 (generated_at 2026-08-18T00:08:14Z, last_modified 2026-08-06T00:07:43Z), Statuspage (page.updated_at, per-component updated_at), Wikipedia REST summary (revision + timestamp), GitHub releases (published_at). The legacy endoflife v0 API is still live and carries neither — its staleness is unmeasurable.
- One URL shape beats seven rows. api.deps.dev/v3 answers 'is it deprecated / is it vulnerable / when was it published' for npm, PyPI, cargo, Maven, Go, NuGet and RubyGems in a single 969-byte version-level document (isDeprecated, deprecatedReason, advisoryKeys[], publishedAt, licenses) — WebFetch-verified 2026-08-18. It collapses the whole registry family into one recipe AND is the GET-shaped replacement for OSV's POST-only query API.
- Two-step entity resolution as the general pattern for structured sources: resolve the identifier first (wbsearchentities -> QID; api.w3.org listing -> shortname; datasets-server /splits -> config+split), then query. A SPARQL query against a guessed QID returns an empty bindings array indistinguishable from a genuine absence — the same silent-zero class the skill already warns about for site: misses.
- Ask a registry for its own latest, explicitly. The official MCP registry's unfiltered listing returns rows with isLatest:false; passing ?version=latest or ?updated_since=<ISO8601> is what makes the answer current. WebFetch-verified 2026-08-18: with version=latest the head row returned status "active", isLatest true.
- Prefer the smallest document that answers the question, everywhere. registry.npmjs.org/{pkg}/latest is 3,508 B and correct; the bare packument is 804,975 B and WebFetch's truncated read of it reported express as deprecated (harvested from 0.x entries). Same asymmetry: pypi /{pkg}/{version}/json 11,872 B vs 192,973 B; deps.dev versions/{v} 969 B vs 56,377 B.

## Tips & gotchas

- TRANSPORT IS PART OF THE CLAIM — curl-reachable and WebFetch-reachable differ in BOTH directions. crates.io/api/v1/crates/serde returns 403 to a bare curl ('API data access policy') and 200 to WebFetch and to curl with a contact UA (re-confirmed 2026-08-18: 403 bare / 200 at 432,647 B with UA); api.stackexchange.com returns 200 to curl and 'Claude Code is unable to fetch from api.stackexchange.com' to WebFetch. A Bash liveness sweep of the catalog will mark live rows dead and dead rows live.
- REDDIT IS UNREACHABLE AND HAS NO FALLBACK — four routes, all dead 2026-08-18. WebFetch on www.reddit.com and old.reddit.com returns a harness-level error, not an HTTP status (a tool denylist no header can defeat); browser-UA curl on /search.json returns 403 with a 189,908-byte HTML anti-bot body; r.jina.ai fetches successfully and relays Reddit's own block page verbatim; api.pullpush.io returns 429 with 'This website does not provide free scraping resources for agents.' Only OAuth (key + POST) remains.
- A `.json` path answering with content-type text/html is a block page, not data. Any recipe whose success check is 'HTTP 200' rather than 'parses as JSON with the expected top-level key' will ingest a block page or a marketing page as evidence — measured on Reddit (403+HTML), status.vercel.com and status.redis.io (200+HTML), and code.claude.com where all 8 guessed feed paths returned 200 with 503,088 B of SPA HTML.
- ZERO-RESULT AND BLOCKED MUST BE DISTINGUISHABLE WITHOUT A HUMAN — three zero-shaped-but-not-absent cases: an over-quoted Discourse query returns 200 with every array empty and every more_* null (retry loosened); a GitHub `repo:` discussions query returns result_count 0 when Discussions are DISABLED (confirm by fetching /{owner}/{repo}/discussions); a WAF 403 on /site.json (community.cloudflare.com, a genuine Discourse instance) means inconclusive, never 'not a forum'.
- GITHUB'S UNAUTHENTICATED CEILING IS 60 REQUESTS/HOUR PER EGRESS IP, SHARED ACROSS EVERY GITHUB ROW — and I measured it exhausted mid-session: api.github.com/rate_limit returned core {limit:60, remaining:0, used:60} on 2026-08-18, after which advisories and releases/latest both returned 403. Under a wide fan-out that 403 reads as a dead endpoint, not a quota. Search is a separate, tighter 10/MINUTE bucket. releases.atom and raw.githubusercontent.com are unmetered substitutes.
- WEBFETCH TRUNCATES HEAD-FIRST with a literal '[Content truncated due to length...]' marker, and its answer about a large body is computed over that slice. It reported express as deprecated from the 805 KB packument, said the packument had no `time` object, and named 2025-08-05 directories as 'the last 3' of a 134-entry listing whose true tail is 2025-12-15. Never ask a recipe for 'the latest' or 'the top N' of an unbounded list; pin the version or narrow the query.
- WEBFETCH RETURNS CROSS-HOST REDIRECTS INSTEAD OF FOLLOWING THEM, and this family is full of them: status.anthropic.com -> status.claude.com, status.slack.com -> slack-status.com, status.aws.amazon.com/data.json -> health.aws.amazon.com/public/currentevents (served as UTF-16), status.vercel.com -> www.vercel-status.com (2 hops), docs.anthropic.com -> platform.claude.com, lmarena.ai -> arena.ai. Each costs a wasted lane call unless the catalog names the post-redirect host.
- TAG != RELEASE != STABLE. kubernetes/kubernetes /tags?per_page=5 returned five prereleases; /releases?per_page=5 led with a prerelease rc and is created_at-ordered (v1.35.7 above v1.37.0-beta.0); vercel/next.js releases.atom led with v16.3.1-canary.22 while stable was v16.3.1. Only /releases/latest carries non-prerelease, non-draft semantics.
- DEPRECATION IS A PER-VERSION STRING, NOT A PACKAGE BOOLEAN — npm's `deprecated` (absent when healthy), PyPI's per-release `yanked`/`yanked_reason`, crates.io's per-version `yanked`. Reading it off an aggregate document reports the status of long-dead releases. PyPI has no package-level deprecation concept at all, so absence of `yanked` says nothing about maintenance.
- AN NPM PACKAGE NAME IDENTIFIES NEITHER THE REPO, ITS GRANULARITY, ITS OWNER, NOR THE MAINTAINED PRODUCT LINE — four modes measured: vue -> vuejs/core (name mismatch); @types/node -> DefinitelyTyped with repository.directory types/node (monorepo); rxjs declares reactivex/rxjs which GitHub resolves to ReactiveX/rxjs (moved owner); aws-sdk is end-of-support while @aws-sdk/client-* is current (superseded line). Corollary: repo pushed_at is a FALSE maintenance signal for monorepo packages, and archived=false does not mean maintained (request/request: archived false, pushed_at 2024-08, explicitly deprecated on npm).
- MAVEN'S SEARCH INDEX IS ~4 MONTHS STALE RIGHT NOW — search.maven.org/solrsearch reports guava 33.4.8-jre while repo1.maven.org's maven-metadata.xml reports <release>33.7.1-jre</release> with lastUpdated 20260818035315. A currency question answered from a registry's SEARCH tier is answered wrong, silently and plausibly. Same class: NuGet's flat-container versions[-1] is a prerelease (13.0.5-beta1), not the stable 13.0.4.
- DEPRECATION/SUNSET HTTP HEADERS ARE VAPOR IN PRACTICE — a sweep of 9 reachable public endpoints found ZERO carrying Deprecation, Sunset or Warning, despite RFC 9745 and RFC 8594 defining them. Absence of the header must map to 'no information', never to 'not deprecated'; the real signals are endoflife's eolFrom, a registry's deprecation flag, and migration-guide prose.
- KEY-REQUIRED OR STRUCTURALLY UNREACHABLE, recorded so a future lane does not re-derive them: OSV /v1/query and /v1/querybatch (405, POST-only); GHCR (needs a token then an Authorization header on a second call — WebFetch cannot set headers); GitHub GraphQL and CODE search (POST/token, 401); Socket.dev (401); Snyk REST API and Artificial Analysis (401); Google Cloud Billing (403); api.podcastindex.org (403, key+HMAC); openai.com/api/pricing/ (hard 403 to BOTH WebFetch and curl); StackShare (429 on one cold request); PulseMCP v0.1 (401, no self-serve signup). Libraries.io inverts the rule — NO api_key returns 200, an INVALID one returns 403, at ~10 req/window.
- TWO ROWS ARE LIVE BUT UNSTABLE AND NEED A DATED RE-CHECK, NOT A STABLE ENTRY: registry.smithery.ai answers keyless 200 while the vendor documents it as bearer-gated; skills.sh/api/search self-labels "searchVersion":"legacy" while every documented /api/v1/* route returns 401 authentication_required.
- MCP DIRECTORIES ARE MOSTLY SPA SHELLS, AND A 404 WITH text/html IS A WRONG-HOST SIGNAL, NOT AN EMPTY RESULT: smithery.ai/api/servers (404, 112 KB Next.js shell — the API host is registry.smithery.ai), mcp.so/api/servers (404 SPA), api.mcp.so (502), mcpservers.org/api/servers (404 SPA), mcpmarket.com/api/servers (403). PulseMCP v0beta returns 410 with a self-describing RANDOMIZED sunset (1% Jan 2026 -> 50% June -> 100% Sept), so the same URL succeeds and fails nondeterministically and a dead channel reads as flakiness.
- STATIC MANIFESTS AND AWESOME-LISTS NEVER EXPIRE AN ENTRY. anthropics/claude-plugins-official lists 286 plugins with no dates, no install counts and no health field; Glama's MCP API returns rich JSON with ZERO date, version or count field. Both are name-discovery sources only — resolve source.url/repository.url to api.github.com/repos/<o>/<r> for pushed_at and archived before any currency claim, and budget those lookups against the 60/hr quota.
- YOUTUBE TRANSCRIPTS ARE DEAD FROM A WEBFETCH LANE, and the failure is silent: /api/timedtext returns an EMPTY body (not an error) because signed params are now required; r.jina.ai returns only the literal placeholder 'Transcript Follow along using the transcript. Show transcript'; third-party scrapers 403. The metadata Atom feed (?channel_id=UC...) still works. The two spoken-word channels that DO work are InfoQ presentation pages and Podcasting-2.0 <podcast:transcript> targets.
- INFOQ SERVES A 120,840-BYTE HTML BODY ON A 404 — a constructed slug looks like a real page to anything judging by content length or by whether markdown rendered. Arrive only via a WebSearch result URL, never by slug construction. Same class: feeds.transistor.fm/<guessed-slug> returns a hard 404, so resolve a podcast feedUrl from the iTunes search response instead.
- DISCOURSE ANONYMOUS LIMITS FAIL BY BLOCKING, NOT THROTTLING: discourse_defaults.conf on main sets max_reqs_per_ip_per_10_seconds = 50 with max_reqs_per_ip_mode = block. A burst fan-out across lanes hitting one popular instance gets 429s that arrive downstream as thin-but-clean results. Also /t/{id}.json returns only the first ~20 posts of post_stream — one fetch is a sample, not the thread — and there is no search.rss (404), so RSS is not a fallback for a blocked search.json.
- LICENSING AND PARSING TRAPS IN THE STRUCTURED-KNOWLEDGE FAMILY: Wikipedia is CC BY-SA (attribution required) while Wikidata is CC0; the Stack Overflow survey glues label to percentage with no delimiter ('JavaScript66%'), varies denominators per question, and gates its raw dataset behind an ODbL click-through a WebFetch lane cannot complete; chromestatus.com prefixes every response with the XSSI guard `)]}'`; Wikimedia pageviews' final monthly bucket is a boundary artifact (2140 vs a ~90k baseline) and must be discarded; arena.ai's leaderboard carries no last-updated date anywhere and concatenates columns.

## What to research next

- RE-VERIFY THE DIVERSITY TECHNIQUES UNDER A FIXED VERDICT JOIN. The STORM perspective ablation (unique references), the Co-STORM moderator ablation, DIV-SE's approach-name template, CoVe's factored-vs-joint verification, and the contrarian-prompt effect were all partitioned into UNTRUSTED in this run — by the same different-domain rule and 40-char prefix join that recommendations 5 and 6 remove, not by contrary evidence. Re-run those questions after the verify fix lands; they are the entire evidence base for the lens/novelty half of the operator's ask.
- MEASURE THE ACTUAL METRIC, BEFORE AND AFTER: distinct registrable domains and distinct source classes cited per brief, against the n=1 baseline (5 URLs, 3 domains, all vendor-owned). Everything here is a hypothesis about that number until two briefs exist to compare. Recommendation 8 makes it computable at zero model cost.
- ENUMERATE WEBFETCH'S HOST DENYLIST. Two hosts are confirmed refused at the tool level regardless of HTTP status (www.reddit.com / old.reddit.com, api.stackexchange.com) and the refusal is a harness error, not a status code — so it reads as a dead source. Nothing tells the catalog which other hosts are on it; a systematic probe would prevent cataloguing rows that can never work.
- DECIDE WHETHER THE RESEARCH LANE GETS A WIDENED TOOL GRANT. Several high-value surfaces are structurally unreachable from WebFetch: GHCR (needs a header on a second request), `npx skills find` (Bash, and strictly better than skills.sh/api/search), OSV bulk data, and any recipe needing jq over a large JSON body. Either grant Bash to one lane or accept the ceiling explicitly — do not leave dead recipes in the catalog as the current gh/Sourcegraph rows do.
- PRICE THE INLINED MENU. Recommendation 1 adds ~600 prompt tokens to each of N research lanes (and again to N verify lanes if shared). Measure the delta against the 14-call/38-call baseline before deciding how much of the catalog rides inline versus behind an explicit Read of the absolute path.
- SET A RE-CHECK CADENCE FOR THE TWO UNSTABLE ROWS AND THE QUOTA-SHADOWED ONE: registry.smithery.ai (undocumented keyless 200), skills.sh/api/search (self-labelled legacy while v1 is 401), and the GitHub Advisory row (which I could not re-verify because core quota hit 0/60 mid-session). With no CI in this repo, a dated re-check is the only mechanism that exists.
- SETTLE WHETHER A SATURATION ROUND EARNS ITS CALL. Recommendation 13 is the only proposal that adds agent calls, and its supporting evidence (returns-curve shape, gap-critic value, premature-stopping cost) is entirely in the untrusted set. Re-verify before spending, given investigation is positioned as the cheap always-on gate.
